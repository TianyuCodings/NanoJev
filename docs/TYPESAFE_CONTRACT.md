# TypeSafe question contract and NanoJev encoding

Reviewed on 2026-09-17 against the official pages linked below and the local source. This is a compatibility audit, not a claim that every TypeSafe request or response is already supported. No model or paid API calls are needed for the included checks.

| Area | Official semantics | Current implementation | Remaining work |
| --- | --- | --- | --- |
| State | Text, JSON objects, and arrays carry the shared evaluation context. Related evidence belongs in one state. [State](https://docs.typesafe.ai/concepts/state) | Local inference accepts nonempty string/dict/list. String states are preserved; dict/list states become Python `str(...)` through an f-string. | Define a versioned JSON serializer and recursive JSON validation. Current object encoding uses single quotes, `True`/`None`, and insertion order; it is not canonical JSON. Changing it also changes checkpoint inputs. |
| Question identity | Question IDs identify responses and are absent from model input. Instructions must contain the complete question. [Primitives](https://docs.typesafe.ai/primitives) | Neither request `id` nor `qid` appears in `leaf_tokens`. Renaming either preserves every candidate path. | Preserve this property in future adapters. Do not treat a descriptive ID as an instruction. |
| Independent questions | Questions share state but do not consume each other's answers. Dependent judgments need a subsequent request. [Primitives](https://docs.typesafe.ai/primitives) | Each leaf contains one state, one instruction, and its own candidate. Unrelated questions/states do not change those tokens. The forward pass has no cross-question attention. | These tests establish input isolation, not bitwise output equality across GPU batch shapes. The default encoder still writes the state into every candidate path. A shared-prefix encoder that evaluates each state/question prefix once is available, is numerically equivalent, and cross-question prefix reuse is still not attempted; see [shared-prefix encoding](SHARED_PREFIX.md). |
| Noul versus Boolean | The direct API uses `type: "noul"`, returns `noul = P(yes)`, and accepts optional true/false criteria. There is no separate Noul confidence. [Noul](https://docs.typesafe.ai/primitives/noul) | This project's AI SDK gateway wrapper and local schema use `type: "boolean"`. The wrapper reads `answer.probability`; local inference returns `p_true`, a two-entry distribution, and a thresholded value. Both textual criteria are encoded in fixed false-then-true order. | A direct TypeSafe compatibility layer must explicitly map names and response fields. Local `type: "noul"` currently fails validation. The probability judges the complete proposition, not a label suggested by its ID. |
| Choice | Both option names and descriptions are semantic inputs. The response contains the chosen option and every option's probability; the documented maximum is 255 options. [Choice](https://docs.typesafe.ai/primitives/choice) | Local requests require 2–255 textual options; a leaf contains `option_key: description`. Reordering options preserves their named leaf inputs. An optional set head combines candidates within the same Choice question. | Add structured/null descriptions and align wrapper limits. `teachers.mjs` only checks that the map is nonempty, so its local checks are less restrictive than the predictor's. |
| Score | There are 2–10 ordered descriptive levels. Each level is evaluated independently; the number comes from its array position. The returned score is the probability-weighted level index. [Score](https://docs.typesafe.ai/primitives/score) | Each leaf contains only its own description, with no injected index or adjacent descriptions. The model's set-attention path is restricted to Choice. Local `score = sum(i * p_i)` and `level` is the argmax. | Full response parity still needs `legend` and `confidence`. Level descriptions must be self-contained; moving a description changes its reported index, not its leaf input. Changing other levels can still change normalized probabilities. |
| Structured entries | Instructions, Choice descriptions, Score entries, and Noul true/false values support strings, objects, arrays, or null. [Advanced structure](https://docs.typesafe.ai/primitives/advanced) | Local prediction requires nonempty strings for instructions and descriptions. `teachers.mjs` accepts object/array instructions and structured/null descriptions, but rejects null instructions. | Define shared, versioned encoding for these entry types. Passing a structured question through the gateway does not make that same question trainable or inferable locally. |
| Response fields | Choice includes confidence; Score also includes a level legend. Both return complete distributions. [Choice](https://docs.typesafe.ai/primitives/choice), [Score](https://docs.typesafe.ai/primitives/score) | The gateway wrapper retains native answers, rounding, and provider confidence metadata. Local answers expose full probabilities and decision values, but omit confidence and Score legend. | Implement explicit response adaptation if wire compatibility is needed. A normalized distribution alone does not establish empirical probability calibration. |
| Task composition | The intended primitive is a focused judgment; code composes multiple answers into a larger decision. [Primitives](https://docs.typesafe.ai/primitives) | One-step collision questions are atomic geometry judgments. Whole-map shortest-path action and distance questions are a separate planning stress profile. | Report these profiles separately. Good local safety accuracy is not evidence of long-horizon navigation performance. |

## The two JavaScript evaluation routes

[`scripts/teachers.mjs`](../scripts/teachers.mjs) has distinct implementations:

- The `jev` route passes the validated request to `experimental_evaluate`, retains the complete native probability mapping, and records declared rounding. Its public question spelling is the gateway SDK's `boolean`, not the direct TypeSafe API's `noul`.
- The `llm` route sends `JSON.stringify({state, questions})` to a generative model and validates hard JSON labels. That prompt exposes question IDs, all questions, and all Score levels together. Asking the model to answer independently does not enforce the input isolation tested for local inference. This route is an alternative label interface, not a test of the native question contract.

The audit inspected the wrapper source; it did not invoke a provider or certify the gateway's internal preprocessing.

## Offline checks

```bash
python3 -m unittest discover -s scripts -p test_question_contract.py -v
```

[`test_question_contract.py`](../scripts/test_question_contract.py) uses a reversible character tokenizer and the real [`prepare_examples`](../scripts/predict_toy_decisions.py) function. It covers transport-ID invariance, unrelated-question/state isolation, Boolean boundary criteria, Choice names/descriptions, Score index/neighbor exclusion, and expected-score readout. It also explicitly characterizes currently rejected structured inputs and noncanonical state serialization.

These tests load no checkpoint, import no PyTorch, download no tokenizer, and make no network requests. They check actual encoded inputs, not model accuracy, semantic equivalence of differently worded questions, calibrated probabilities, or GPU numerical reproducibility.
